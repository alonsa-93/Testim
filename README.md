# Testim — מערכת עיצוב לדפי נחיתה

מערכת עיצוב (Design System) רב-לקוחית לבניית אתרים ודפי נחיתה בעברית, ב-RTL מלא.
שלושה חלקים שעובדים יחד:

1. **מנוע ערכות (Themes)** — כל העיצוב של דף מוגדר בקובץ JSON אחד: צבעים,
   פונטים, עיגול פינות, ריווחים וצללים. החלפת קובץ = מראה חדש, בלי לגעת בקוד.
2. **ספריית בלוקים** — רכיבים מוכנים לדפי נחיתה (Hero, יתרונות, המלצות,
   מחירון, שאלות נפוצות, טופס לידים ועוד) שצורכים אך ורק את הטוקנים של הערכה.
3. **סטודיו ויזואלי** — ממשק שבו גם מי שלא יודע קוד מכוון צבעים ופונטים,
   רואה את הדף מתעדכן בזמן אמת, ומייצא קובץ ערכה מוכן.

## הרצה

```bash
npm install
npm run dev
```

| כתובת | מה רואים |
|---|---|
| `/` | דף נחיתה לדוגמה + ווידג'ט החלפת ערכות חי |
| `/studio` | הסטודיו הוויזואלי — עריכת ערכה עם תצוגה חיה |
| `/preview/default` | הדף תחת ערכת "פרימיום נקי" |
| `/preview/nova-dark` | אותו דף בדיוק תחת ערכת הלקוח "נובה" |

## איך זה עובד — זרימת הטוקנים

```
themes/<לקוח>.json  →  themeToCssVars()  →  משתני CSS ‏(--ds-*)
                                              ↓
                      app/globals.css — ‏@theme inline ממפה אותם
                      ליוטיליטיז של Tailwind‏ (bg-primary, text-ink,
                      rounded-card, py-section...)
                                              ↓
                      הבלוקים משתמשים רק ביוטיליטיז האלה —
                      ולכן כל ערכה מעצבת אותם מחדש אוטומטית
```

- `lib/theme.ts` — הגדרת מבנה הערכה (`Theme`), רשימת הפונטים, וההמרה למשתני CSS.
- `lib/contrast.ts` — חישובי ניגודיות לפי WCAG 2.2 (משמש את הסטודיו).
- `themes/` — קובצי הערכות + `index.ts` שרושם אותן במערכת.
- `components/ui/` — רכיבי בסיס: `Button`, `Card`, `Badge`, `Field`, `Section`.
- `components/blocks/` — הבלוקים של דפי הנחיתה.
- `components/studio/` — הסטודיו הוויזואלי.

## הוספת לקוח חדש (ערכה חדשה)

1. פותחים את `/studio`, בוחרים ערכת בסיס ומכוונים צבעים, פונטים וצורה.
2. בפאנל "נגישות" מוודאים שכל הצירופים ירוקים (יש כפתור "תקן" אוטומטי).
3. נותנים לערכה שם ומזהה באנגלית (למשל `dana-clinic`) ולוחצים **הורדת הערכה**.
4. שומרים את הקובץ בתיקיית `themes/` ומוסיפים שתי שורות ב-`themes/index.ts`:

```ts
import danaClinic from "./dana-clinic.json";
// ...
export const themes: Theme[] = [
  defaultTheme as Theme,
  novaDark as Theme,
  danaClinic as Theme, // ← חדש
];
```

מרגע זה הערכה זמינה ב-`/preview/dana-clinic`, בסטודיו ובווידג'ט ההחלפה.

## בניית דף נחיתה חדש

`components/landing-page.tsx` הוא ההרכבה לדוגמה. לדף חדש:

1. יוצרים route חדש (למשל `app/dana/page.tsx`).
2. מרכיבים בו את הבלוקים הרצויים ועוטפים בערכת הלקוח:

```tsx
import { themeToStyle } from "@/lib/theme";
import { getTheme } from "@/themes";

export default function DanaPage() {
  const theme = getTheme("dana-clinic")!;
  return (
    <div style={themeToStyle(theme)} className="min-h-screen bg-bg text-ink">
      {/* Navbar, Hero, LeadForm... */}
    </div>
  );
}
```

3. תוכן (טקסטים) עורכים כרגע בקוד הבלוקים או דרך props — עריכת תוכן
   ויזואלית היא שלב עתידי במפת הדרכים.

## RTL ונגישות — מה כבר מובנה

- כל הרכיבים משתמשים ב-logical properties בלבד (`ps-`, `me-`, `start-`,
  `text-start`) — הדפים יעבדו גם ב-LTR אם תוסיפו שפה שנייה.
- HTML סמנטי, ניווט מקלדת מלא, טבעת פוקוס אחידה, קישור "דילוג לתוכן",
  `aria` בטופס ובתפריט המובייל, ו-`prefers-reduced-motion`.
- הסטודיו כולל **בדיקת ניגודיות חיה** לפי WCAG 2.2, כדי שלקוח לא ייצר
  בטעות ערכה לא נגישה.
- שימו לב: אלו בדיקות טכניות — לפני עליית אתר אמיתי לאוויר נדרשת עדיין
  בדיקת נגישות מלאה, השלמת הצהרת הנגישות ומדיניות הפרטיות
  (יש תבניות placeholder ב-`/accessibility` ו-`/privacy`).

## מה עוד לא כלול (מפת דרכים)

- **שליחת הטופס** — הטופס מדמה הצלחה; יש לחבר API / CRM / אימייל
  בנקודה המסומנת ב-`components/blocks/lead-form.tsx`.
- **אחסון ערכות במסד נתונים** — כרגע ערכות הן קבצים בריפו (פשוט וגיטי);
  כשיהיו הרבה לקוחות אפשר לעבור ל-Supabase בלי לשנות את הרכיבים.
- **עריכת תוכן ויזואלית** — הסטודיו עורך עיצוב בלבד, לא טקסטים.
- **אנליטיקס ועוגיות** — לא הותקנו בכוונה; אם תוסיפו, חובה לעדכן את
  מדיניות הפרטיות ולהוסיף מנגנון הסכמה.
