# Testim — מערכת לבניית דפי נחיתה

מערכת רב-לקוחית לבניית אתרים ודפי נחיתה בעברית, ב-RTL מלא.
בונים דף מהסטודיו — בוחרים בלוקים, כותבים תוכן, מכוונים עיצוב — ומקבלים
דף חי, בלי לכתוב שורת קוד.

> **חדש כאן?** המדריך המעשי המלא — בניית דף ללקוח מ-א׳ עד ת׳, סדר
> בלוקים מומלץ, כללי קופי וצ׳ק-ליסט מסירה — נמצא ב-**[GUIDE.md](GUIDE.md)**.

ארבעה חלקים שעובדים יחד:

1. **בלוקים** — חלקי דף מוכנים (Hero, שירותים, המלצות, מחירון, טופס לידים…).
2. **ערכות נושא** — כל העיצוב בקובץ JSON אחד: צבעים, פונטים, פינות, ריווחים.
3. **דפים** — קובץ JSON שאומר אילו בלוקים בדף, באיזה סדר, ומה כתוב בהם.
4. **סטודיו** — הממשק שמרכיב את שלושת אלה, עם תצוגה חיה ובדיקת נגישות.

```bash

```

## לבנות דף נחיתה חדש — הזרימה המלאה

1. נכנסים ל-`/studio`, לוחצים **דף חדש וריק** (או מתחילים מדף הדוגמה).
2. בטאב **מבנה ותוכן**: לוחצים ״+ הוספת בלוק״ ובוחרים מה ייכנס לדף.
   מסדרים בחיצים ↑↓, מוחקים ב-✕.
3. לוחצים על בלוק כדי לערוך את כל הטקסטים שלו. רשימות (שירותים, המלצות,
   מסלולים) נערכות פריט-פריט, עם הוספה, סידור ומחיקה.
4. בטאב **עיצוב**: בוחרים צבעים ופונטים. פאנל הנגישות בודק ניגודיות בזמן
   אמת ומציע תיקון אוטומטי.
5. ממלאים שם ומזהה לדף (למשל `dana-clinic`) ולוחצים **הורדת הדף**.
6. שומרים את הקובץ בתיקיית `pages-data/` ומוסיפים שתי שורות ב-`pages-data/index.ts`:

```ts
import danaClinic from "./dana-clinic.json";

export const pages: Page[] = [
  demo as Page,
  danaClinic as Page, // ← חדש
];
```

הדף עולה בכתובת `/p/dana-clinic`.

הכול נשמר אוטומטית בדפדפן תוך כדי עבודה, כך שסגירה בטעות לא מאבדת את
הטיוטה. **הורדת הדף** היא מה שהופך אותה לקבועה.

## איך זה בנוי מבפנים

```
pages-data/<דף>.json   →  אילו בלוקים, באיזה סדר, ומה כתוב בהם
themes/<ערכה>.json     →  איך הכול נראה
        ↓                        ↓
   PageRenderer          themeToCssVars() → משתני CSS ‏(--ds-*)
        ↓                        ↓
   הבלוקים מרונדרים    globals.css ממפה אותם ליוטיליטיז של Tailwind
                        (bg-primary, text-ink, rounded-card, py-section)
```

הבלוקים משתמשים רק ביוטיליטיז האלה, ולכן **כל ערכה מעצבת כל דף** — ללא
קוד ייעודי.

- `lib/theme.ts` — מבנה הערכה, רשימת הפונטים, המרה למשתני CSS.
- `lib/page.ts` — מבנה הדף.
- `lib/fields.ts` — סכמת השדות שממנה הסטודיו בונה טפסי עריכה.
- `lib/contrast.ts` — חישובי ניגודיות לפי WCAG 2.2.
- `components/blocks/` — הבלוקים + `registry.ts` שמרכז אותם.
- `components/studio/` — הסטודיו.
- `themes/`, `pages-data/` — התוכן שלך: ערכות ודפים.

## הוספת בלוק חדש למדף

קובץ אחד + שתי שורות ב-registry (import + הוספה למערך). הבלוק מצהיר על
תוכן ברירת מחדל ועל השדות שניתן לערוך, והסטודיו בונה לו ממשק עריכה לבד.
הדוגמה כאן היא בלוק "צוות" — שלא קיים היום במדף ה-15, כדי שאפשר יהיה
לבצע אותה מילה במילה:

```tsx
// components/blocks/team.tsx
export const teamBlock: BlockDef = {
  type: "team",
  label: "הצוות",
  description: "רשת כרטיסי חברי צוות",
  component: Team,
  defaults: defaults as unknown as BlockContent,
  fields: [
    { key: "title", type: "text", label: "כותרת" },
    { key: "members", type: "list", label: "חברי הצוות", itemLabel: "חבר צוות",
      titleKey: "name",
      fields: [
        { key: "name", type: "text", label: "שם" },
        { key: "role", type: "text", label: "תפקיד" },
      ] },
  ],
};
```

```ts
// components/blocks/registry.ts
import { teamBlock } from "./team";     // 1. שורת import למעלה

export const blockDefs: BlockDef[] = [
  // ...
  teamBlock,                            // 2. הוספה למערך
];
```

## הוספת ערכת עיצוב ללקוח

בסטודיו, טאב **עיצוב** ← לכוונן ← **הורדת הערכה** ← לשמור ב-`themes/`.
אותו דפוס שתי-שורות כמו בלוק:

```ts
// themes/index.ts
import leviClinic from "./levi-clinic.json";   // 1. שורת import למעלה

export const themes: Theme[] = [
  defaultTheme as Theme,
  novaDark as Theme,
  leviClinic as Theme,                          // 2. הוספה למערך
].map(normalizeTheme);
```

הערכה תופיע כאפשרות בסטודיו וב-`/preview`.

## טיפים לעריכה

- בכותרת הראשית, טקסט בין `**` `**` מקבל את צבע המבטא:
  `בית שמרגיש **בדיוק** כמו שדמיינתם`.
- שדה טקסט שנשאר ריק פשוט לא מוצג (למשל כפתור משני, ציטוט צף).
- הניווט והפוטר נעוצים תמיד לראש הדף ולתחתיתו, כדי לשמור על מבנה HTML תקין.
- קישורי הניווט הם עוגנים לסקשנים: `#features`, `#pricing`, `#contact`.

## RTL ונגישות — מה כבר מובנה

- כל הרכיבים משתמשים ב-logical properties בלבד (`ps-`, `me-`, `start-`,
  `text-start`) — הדפים יעבדו גם ב-LTR אם תוסיפו שפה שנייה.
- HTML סמנטי, ניווט מקלדת מלא, טבעת פוקוס אחידה, קישור ״דילוג לתוכן״,
  `aria` בטופס ובתפריט המובייל, ותמיכה ב-`prefers-reduced-motion`.
- בדיקת ניגודיות חיה בסטודיו לפי WCAG 2.2, עם תיקון אוטומטי.
- שימו לב: אלו בדיקות טכניות. לפני עליית אתר אמיתי לאוויר נדרשת בדיקת
  נגישות מלאה, והשלמת הצהרת הנגישות ומדיניות הפרטיות (תבניות מסומנות
  ב-`/accessibility` ו-`/privacy`).

## מה עוד לא כלול (מפת דרכים)

- **שליחת הטופס** — הטופס מדמה הצלחה; יש לחבר API / CRM / אימייל בנקודה
  המסומנת ב-`components/blocks/lead-form.tsx`.
- **תמונות בהירו ובאודות** — קומפוזיציות צבע דקורטיביות (בגלריה כבר
  אפשר להדביק כתובת תמונה). העלאת תמונות היא השלב הבא הטבעי.
- **שמירה בענן** — הדפים הם קבצים בריפו (פשוט וגיטי). עם הרבה לקוחות
  אפשר לעבור ל-Supabase בלי לשנות בלוק אחד.
- **עריכה בלחיצה על התצוגה** — כרגע עורכים מהפאנל בצד.
