## 1. מתודולוגיית ההכרעה (רטרואקטיבית לביקורת 21/08)

לכל פקד בסטודיו הופעלו שני מבחנים:

1. **"נחוץ למשימה נפוצה?"** — האם רוב המשתמשים נוגעים בזה ברוב
   הפעמים שהם עורכים ערכה/עמוד/סצנה?
2. **"משפר את התוצאה או רק מדגים יכולת?"** — האם הפקד הזה עוזר
   להגיע לתוצאה טובה יותר, או שהוא בעיקר "כי אפשר"?

התוצאה מוינה לשש קטגוריות: **Keep גלוי / Simplify / Combine /
Contextual (הצג רק כשרלוונטי) / Advanced (מקופל מאחורי ⚙) / Remove**.
אף אחת מהן לא הייתה "מחק יכולת" בפועל — כל הפרמטרים שהיו קיימים ב-
20/08 עדיין נגישים היום, רק ברמת חשיפה שונה.

## 2. מה שכבר קיים בקוד (מאומת — לא רק "בוצע" אלא נבדק כרגע)

| החלטה | מימוש | קובץ |
|---|---|---|

| **תיקון קולנועי** — preset "קולנועי" קיבל רקע כהה + תיקון גודל כותרת גדולה (`.exp-motion h1-h4`) שנחשף כבאג אמיתי במהלך הביקורת | CSS rule חדש | `app/globals.css` |

**מדידה:** גלילת טאב "עיצוב" בסטודיו צומצמה מ-3,547px ל-1,584px
(-55%) עם 0 יכולות שהוסרו — כל שינוי שהיה אפשרי ב-20/08 עדיין אפשרי
היום, בפחות קליקים/גלילה לתרחיש הנפוץ.

**מה זה לא פותר** (ומטופל ב-Milestone D, לא כאן): הבעיה המבנית —
כל הפקדים חיים באותו `<aside>` שמאלי יחיד, אז עריכת שכבה **מחליפה**
את רשימת הסצנות (לא מוסיפה פאנל), והקנבס לא לוקח את מרבית המסך.
צמצום 21/08 הוא צמצום **תוכן** בתוך פאנל; Milestone D הוא שינוי
**מבנה** (כמה פאנלים, איפה, מה גודל הקנבס).

## 3. ה-IA החדש (Milestone D — התכנון המחייב)

```
┌─────────────────────────── TOP ───────────────────────────┐
│ שם עמוד · מתג Standard/Experience · ⚙ הגדרות · פרסום        │
├────────┬──────────────────────────────────┬────────────────┤
│  LEFT  │                                  │     RIGHT      │
│ מבנה   │                                  │  מאפיינים      │
│        │            CENTER                │  קונטקסטואלי   │
│ Experience:          קנבס דומיננטי         │                │
│  רשימת │  (הסצנה הנוכחית, קומפוזיציה,      │  ראו §3.2 —    │
│  סצנות │   בחירה על-קנבס, גבולות סצנה)     │  תלוי מה נבחר  │
│        │                                  │                │
│ Standard:                                 │                │
│  רשימת │                                  │                │
│  בלוקים│                                  │                │
├────────┴──────────────────────────────────┴────────────────┤
│         BOTTOM — טיימליין (רק כשסצנה נבחרה)                  │
│         scrubber + keyframe markers                          │
└────────────────────────────────────────────────────────────┘
```

### 3.1 עקרונות מחייבים ל-D

- **CENTER תופס את רוב הרוחב.** LEFT ו-RIGHT הם פאנלים צרים
  (~280-320px), לא ה-380px-אחד-עושה-הכול הקיים.
- **LEFT ו-RIGHT נפרדים תמיד** — עריכת שכבה לא "בולעת" את רשימת
  הסצנות; שניהם גלויים בו-זמנית (בדסקטופ). זה ההבדל המבני המרכזי
  מהיום.
- **BOTTOM מופיע/נעלם** לפי הקשר — אין סצנה נבחרת ⇒ אין טיימליין
  (אין למה לגלול scrubber).
- **מסכים צרים של הסטודיו עצמו**: LEFT/RIGHT הופכים ל-drawers
  (נפתחים מעל הקנבס, לא לצידו) — הקנבס נשאר במרכז תמיד.

### 3.2 עריכה קונטקסטואלית — טבלת מיפוי (RIGHT panel)

| מה נבחר (state) | מה מוצג ב-RIGHT | מקור (רכיב קיים לשימוש חוזר) |
|---|---|---|
| כלום נבחר | הגדרות Experience כלליות (defaultEasing, performance mode, motion budget) | חלק מ-`ExperienceEditor` הקיים |
| Scene (בלי layer) | שדות הסצנה: שם/קומפוזיציה/pinned/duration/transition/background | `ExperienceSceneEditor` הקיים (הפרדה בין רשימת השכבות ל-LEFT לבין שדות הסצנה ל-RIGHT) |
| Layer | 4 טאבים (Basic/Style/Motion/Advanced) | `ExperienceLayerInspector` הקיים — **ללא שינוי לוגי**, רק הזזה למיקום RIGHT |
| Track/keyframe בודד (מתוך scrubber) | פרטי ה-keyframe הנבחר (ערך, easing, מיקום בזמן) | חדש (Milestone D3), בונה על מבנה ה-Motion tab הקיים |

**עיקרון**: D3 הוא **הזזה, לא שכתוב** — `ExperienceLayerInspector`
ו-`ExperienceSceneEditor` נשארים אותם רכיבים לוגיים, רק עוברים
מיקום מ"כל הפאנל השמאלי" ל"פאנל ימני קונטקסטואלי", ורשימת
הסצנות/שכבות (הניווט המבני) נשארת קבועה ב-LEFT ולא נעלמת בזמן
עריכה.

### 3.3 מה חדש לעומת הקיים (לא הזזה בלבד)

- **בחירה-על-קנבס** (D1): קליק על שכבה ב-CENTER קורא ל-`onSelectLayer`
  (state קיים, כיוון חדש — קנבס→state, בנוסף לכיוון הקיים state→פאנל).
- **Keyframe markers על ה-scrubber** (D2): ה-`<input type="range">`
  הקיים מקבל שכבת overlay שמסמנת את מיקומי ה-keyframes של ה-track
  הפעיל, לא שינוי למנגנון `scrollToProgress` עצמו.
- **שכפול סצנה** (D4): כפתור חדש ב-LEFT, קורא ל-`instantiatePresetScene`
  הקיים (remap ids) על הסצנה הנבחרת במקום על preset.
